## 前端页面性能如何优化



```
加载阶段
├── 减少体积    → 代码分割、Tree-shaking、图片压缩
├── 加快传输    → CDN、Gzip/Brotli、HTTP/2
└── 减少请求    → 强缓存、合并请求

解析渲染阶段
├── 减少阻塞    → 关键 CSS 内联、JS defer/async
├── 优先关键    → preload、preconnect、fetchpriority
└── 减少重排    → 明确图片宽高、避免动态插入内容

运行时阶段
├── 减少计算    → 防抖节流、虚拟列表、Web Worker
├── 减少渲染    → v-memo、shouldComponentUpdate
└── 延迟加载    → 路由懒加载、图片懒加载、组件懒加载
```

- 懒加载：路由懒加载、图片懒加载（Intersection Observer）
- CDN 缓存策略：强缓存/协商缓存，延长静态资源的缓存时间，webpack 的 contenthash（希望静态资源缓存越久越好，但资源更新后又要让缓存立即失效。解决方案：文件内容变了，文件名就变，URL 变了缓存自然失效）
- Gzip压缩文件大小
- 代码分割：splitChunks 配置，按需加载
- LCP、FMP 的优化思路

```
页面加载时间线

0ms      FCP              FMP              LCP          TTI
├────────┼────────────────┼────────────────┼────────────┤
│        │                │                │            │
开始加载  首次内容渲染      首次有意义渲染    最大内容渲染  可交互
         (有东西出现)      (主要内容出现)    (最大元素)
```

LCP优化：

-  LCP元素通常是首屏大图或 Hero 区域，可以预加载
- SSR：页面HTML结构在服务器端动态生成，随后发送给浏览器直接渲染。

FMP 优化：

- 骨架屏，首先渲染主内容

## 讲讲回流和重绘的区别，如何避免回流和重绘

```
HTML        CSS
 ↓           ↓
DOM树    CSSOM树
  └────┬────┘
    渲染树(Render Tree)    ← 只包含可见节点
       ↓
    Layout（回流）         ← 计算每个节点的位置和尺寸
       ↓
    Paint（重绘）          ← 填充像素颜色
       ↓
    Composite（合成）      ← 多层合并，送显卡输出
```



回流：**几何信息**发生变化，浏览器需要重新计算布局

重绘：元素**外观**发生变化，只需要重新填充像素。

-  用 CSS 类名批量修改样式
- 用 transform 位移（transform在合成处处理）
- 离线操作 DOM
- 脱离文档流再操作
- 避免频繁读取布局属性
- 使用 requestAnimationFrame，将DOM操作推迟到下一帧，让浏览器统一批处理

## 浏览器渲染一帧都做了什么

浏览器渲染一帧（通常在 \(16.7\text{ms}\) 内完成以达到 \(60\text{fps}\)）主要经过以下几个核心步骤：处理输入事件、执行 JavaScript、计算样式（Recalculate Style）、布局（Layout）、绘制（Paint）以及合成（Composite）。其目的是将 HTML/CSS/JS 转换为屏幕上的像素。 [[1](https://juejin.cn/post/7522960183048945704), [2](https://www.cnblogs.com/cangqinglang/p/14688582.html), [3](https://developer.mozilla.org/zh-CN/docs/Web/Performance/Guides/How_browsers_work)]

浏览器渲染一帧的详细流程

1. **处理用户输入事件 (Input Events)**
   - 处理如鼠标点击、滚动、触摸等事件，确保页面响应。
2. **执行 JavaScript (JavaScript)**
   - 运行动画脚本、操作 DOM 或 CSSOM。如果 DOM 改变，可能触发接下来的重排或重绘。
3. **计算样式 (Style / Recalculate Style)**
   - 浏览器解析 CSS，构建 CSSOM 树，并计算每个元素最终的样式（Cascaded Styles）。
4. **布局 (Layout / Reflow)**
   - 根据计算出的样式，计算元素在屏幕上的位置和大小（几何信息）。
5. **绘制 (Paint / Rasterization)**
   - 将层绘制成位图（像素），并生成绘制记录（Painting Records）。
6. **合成 (Composite / Compositing)**
   - 浏览器将图层（Layers）分层并发送给 GPU，由合成器线程将它们合并成最终屏幕图像。
