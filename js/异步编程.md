# 异步编程

### 同步与异步

同步：这件事没做完，下件事就不能开始。（先刷牙，再吃饭）

异步：这件事没做完，下一件事可以其他人去做。（刷牙，同时煮鸡蛋）

浏览器是多线程的：

- GUI渲染线程：渲染和解析页面
- JS引擎线程：渲染和解析JS。浏览器只分配一个线程去解析js，所以js是单线程的
- 定时器监听线程
- 事件监听线程
- HTTP网络请求线程（同源下，浏览器最多同时分配5 ~7个HTTP线程）

JS中的异步操作：借用浏览器的多线程机制，以及事件循环，实现单线程异步效果

### 异步的发展流程

- callback函数（高阶函数）
- Promise
- generator + co
- async + await

写起来越来越像同步代码。

```js
            callback()
        }
    }
}

    console.log("吃完了");
})
```

## Promise

> 为什么叫Promise（承诺/约定）：Promise 对象在创建时，它并没有立即把异步操作（如网络请求）的结果给你，而是给你一个“约定”，最初它处于等待中（`pending`），代表承诺尚未兑现，最终它会给你一个结果：要么成功（`fulfilled`），把数据给你；要么失败（`rejected`），告诉你失败的原因。

多个异步操作依赖时，嵌套层层加深，导致代码可读性差。Promise 是es6新增的内置类（构造函数），也是异步编程的一种解决方案，避免了回调地狱。它不是新的语法功能，而是一种新的写法，允许将回调函数的横向展开，改成纵向展开。

```js
let p1 = new Promise([executor])
```

Promise构造函数只有一个参数，叫做executor执行器，new Promise时就会**立即执行**（即同步执行）

- 私有属性：3个
  - `[[PromiseState]]`：实例的状态。resolve：成功	reject：失败	pending：等待
  - `[[PromiseResult]]`：实例的值。成功的结果或失败的原因
    - `value`：保存成功的结果，可以是undefined/thenable/promise
    - `reason`：保存失败的原因
- 公共方法（由具体的 Promise 实例调用）：then、catch、finally
- 静态方法（Promise 调用）：resolve、reject、all、any、race

```js
p1.then([onfulfilled], [onrejected])
```

- 实例状态是成功时，把实例的值作为成功的结果传递给`onfulfilled`并执行；状态是失败时，把实例的值作为失败的原因传递给`onrejected`并执行

特点：

- Promise可以解决异步问题。但它本身不是异步的。
- Promise支持多个并发的请求

创建Promise实例的三种方法：

- new Promise()
- then方法
- resolve、reject、all、any、race等静态方法

### then

promise实例上的then方法，有两个参数需要用户传入，一个是成功时调用的函数onFulfilled，一个是失败时调用的函数onRejected。then方法是异步调用的。

```js
let p = new Promise((resolve, reject)=>{
    resolve('成功')
});
p.then(
	(value) => { // 成功逻辑
        console.log(result)
    },
    (reason) => { // 失败/错误逻辑
        console.log(reason)
    }
)
```

- `executor`提供了两个方法resolve和reject（Promise内部实现），用于将Promise实例的状态置为成功或失败
  - `resolve('成功')`：把实例p的状态置为`fulfilled`，值（成功结果）为`'成功'`
  - `reject('失败')`：把实例p的状态置为`rejected`，值（失败原因）为`'失败'`。
  - 如果`executor`函数内部执行报错，也把实例p的状态置为`rejected`，值（失败原因）为`报错原因`。（不会抛异常）


一旦状态被置为fulfilled或rejected，状态就不再改变。



> 每次执行then方法，都会返回一个新的Promise实例

```js
let p2 = p1.then(onfulfilled, onrejected);
```

不论`onfulfilled`或`onrejected`方法谁执行，决定p2的状态和值的规则如下：

- 执行报错：p2状态为失败(rejected)，值是失败原因
- 执行不报错，再看方法的返回值
  - 如果返回的是新的promise实例a，则a的状态和值直接决定了p2的状态和值
  - 如果返回的不是promise实例，则==p2状态是成功（fulfilled），值是函数的返回值==

promise的resolve、reject、all、any、race等静态私有方法，也会创建新的promise实例。

- `promise.resolve(10)`：创建一个状态是成功fulfilled，值是10的promise实例
  - `let p = Promise.resolve(10)` 和 `let p = new Promise(resolve => resolve(10))` 基本等价（仅在value是普通值而不是`thenable`时等价），都创建了一个立即成功（fulfilled）的 Promise，值为 `10`。
- `promise.reject(0)`：创建一个状态是失败rejected，值是0的promise实例

注意：

- `Promise.resolve(value)` 如果 `value` 是一个 **thenable**（包括 Promise 实例、任何拥有 `then` 方法的对象或函数），它会直接返回那个 thenable，而不会创建新 Promise。
- `new Promise(resolve => resolve(thenable))` 则会将 `thenable` 包裹在一个新的 Promise 中，并等待其决议。

示例：

```js
let original = new Promise(resolve => setTimeout(() => resolve(1), 1000));
let p1 = Promise.resolve(original);
let p2 = new Promise(resolve => resolve(original));

console.log(p1 === original); // true（返回了原 Promise）
console.log(p2 === original); // false（新 Promise 包装了原 Promise）
```

#### then链的穿透/顺延机制

`.then(onfulfilled, onrejected)`，两个方法可以为空。如果为空，则顺延至下一个then中【相同状态要执行的方法中】去处理。

原理：Promise内部默认将null onfulfilled替换为：`value => { return value }`，将null onrejected替换为`reason => { throw reason; }`

```js
Promise.resolve(10)
    .then(null, null)
    .then(value => {
        console.log('ok', value); // ok 10
    }, reason => {
        console.log('fail', reason);
    })

Promise.reject(10)
    .then()
    .then(value => {
        console.log('ok', value); 
    }, reason => {
        console.log('fail', reason); // fail 10
    })
```

### catch、finally

`p.catch(onrejected)`等价于`p.then(null, onrejected)`

`.catch`总是放在最末尾，且then中只传递`onfulfilled`，是因为无论前面哪个promise失败，都会穿透至结尾的catch里的`onrejected`方法，控制台不报红。

如果没有catch，且出现失败，则控制台会报红，但不影响其他代码执行。



`.finally`：不论成功还是失败，最后都要执行finally中的方法。

### all、any、race

`Promise.all/any/race([promises])` 

- `[promises]`：包含零到多个 Promise 实例的集合，一般是数组。如果集合中的某一项不是promise实例，则默认包装成状态为成功的、值是本身的promise实例
- 返回值是新的Promise实例
- `all`：集合中的**每个**实例都成功，最后结果才是成功，值为多个Promise实例的执行结果组成的数组；只要有一个失败，结果就是失败，值是失败的原因，后面的操作不再处理
- `any`：**只要有一个**成功，最后结果就是成功，值为成功的结果。如果都失败，结果才是失败
- `race`：谁**最快**执行完，谁就是结果（无论成功还是失败）

```js
let p1 = new Promise(resolve => {
    setTimeout(() => {
        resolve(1)        
    }, 3000);
})
let p2 = new Promise(resolve => {
    setTimeout(() => {
        resolve(2)    
    }, 2000);
})

let p3 = Promise.resolve(3)
let p4 = 4 // 默认变为 Promise.resolve(4)

let p = Promise.all([p1, p2, p3, p4])
p.then(value => {
    console.log(value); // [1,2,3,4]
}, reason => {
    console.log('fail', reason);
})
```



传入多个 Promise 组成的数组，返回一个新 Promise，用then获取多个Promise的执行结果组成的数组（前提是这些promise全部执行成功）。如果有一个失败，直接抛出error。

```js
Promise.all([read("1.txt"), read("2.txt")]).then(
    (data) => {
        console.log(data); // [ '2.txt', 'hahahaha' ]
    }
)
```







### 手写

一个基本的promise实现（不考虑链式调用）：

```js
class Promise {
    constructor(excutor) {
        this.status = 'pending'
        this.value = undefined
        this.reason = undefined
        // 存放成功的回调
        this.onResolvedCallbacks = []
        // 存放失败的回调
        this.onRejectedCallbacks = []
        let resolve = (value) => {
            if (this.status == 'pending') {
                this.status = 'resolved'
                this.value = value
                this.onResolvedCallbacks.forEach(fn => fn());
            }
        }
        let reject = reason => {
            if (this.status == 'pending') {
                this.status = 'rejected'
                this.reason = reason
                this.onRejectedCallbacks.forEach(fn => fn());
            }
        }
        try {
            excutor(resolve, reject)
        } catch (e) {
            reject(e)
        }
    }
    then(onFufilled, onRejected) {
        if (this.status === 'resolved') {
            onFufilled(this.value)
        }
        if (this.status === 'rejected') {
            onRejected(this.reason)
        }
        if (this.status === 'pending') {
            this.onResolvedCallbacks.push(() => {
                onFufilled(this.value)
            })
            this.onRejectedCallbacks.push(() => {
                onRejected(this.reason)
            })
        }
    }

}
```

## iterator

Iterator迭代器：一种机制，为各种不同的数据结构提供统一的循环和迭代规范。ES6的`for of`循环本身是基于`Iterator`机制迭代的

拥有Iterator机制的对象，必须具备`next`方法，用它依次访问对象中的每个成员

next返回值：

- value：当前迭代的这一项的值
- done：记录迭代是否完成

```js
class Iterator {
    constructor(assemble) {
        let self = this
        self.assemble = assemble
        self.index = 0
    }
    next() {
        let self = this, assemble = self.assemble
        if (self.index > assemble.length - 1) {
            return {
                value: undefined,
                done: true
            }
        }
        return {
            value: assemble[self.index++],
            done: false
        }
    }
}

let itor = new Iterator([1, 2, 3, 4])
console.log(itor.next());
```

虽然不具备Iterator内置类，但某些数据结构上有`Symbol.iterator`方法，具备迭代器规范：

- Array、Set、Map、String、NodeList、arguments
- Object**没有**`Symbol.iterator`方法，所以普通对象不能使用for of循环

```js
let arr = [1,2,3]
let it = arr[Symbol.iterator]()
console.log(it.next()); 
```



ES6的`for of`循环原理：

- 先去找`[Symbol.iterator]`方法，如果没有，报错`TypeError: xxx is not iterable`
- 每次循环执行一次`itor.next()`，把返回的value赋给循环中的value
- `done`为true后，结束循环

```js
for(let value of arr){
    console.log(value);
}
```





```js
arr[Symbol.iterator] = function () {
    let self = this, index = 0
    return {
        next() {
            if (index > self.length - 1) {
                return {
                    value: self[index++],
                    done: true
                }
            }
            return {
                value: self[index++],
                done: false
            }
        }
    }
}
```

为普通对象手动实现`iterator`：

```js
let obj = { name: 'abc', age: 11 }
obj[Symbol.iterator] = function () {
    let self = this, keys = Reflect.ownKeys(self), index = 0 // 返回一个由self对象自身的属性键组成的数组
    return {
        next() {
            if (index >= keys.length) {
                return {
                    value: undefined,
                    done: true
                }
            }
            return {
                value: self[keys[index++]],
                done: false
            }
        }
    }
}
for (let value of obj) {
    console.log(value);
}
```

或者直接用Array的iterator，前提是对象结构与数组一致（索引、长度）：

```js
let obj = { 0: 'abc', 1: 11 , 2: 22, length: 3};

obj[Symbol.iterator] = Array.prototype[Symbol.iterator];

for (let value of obj) {
    console.log(value);
}
```

### js中的各种循环性能

for、while、forEach、for of、for in

密集数组：有效元素个数就是数组长度

稀疏数组：数组长度大于有效元素个数。例如：`[0:1, 2:11, length = 5]`

- `forEach` 作为内部封装的方法，内部做了一些逻辑判断，稍微比命令式编程慢些
- `for in`会依次查找私有和原型链上所有可枚举的属性，最慢，不建议使用

## generator

 生成器函数`function* fn() {}`，通过`yield`和`next`控制函数体中的代码一步步执行。

`fn(10, 20)`：

- 函数体中的代码并没有执行
- 返回一个具备迭代器iterator规范的对象，具有next、return、throw方法
- 原型链：`itor` -> `fn.prototype` -> `GeneratorFunction.prototype(next/return/throw)` -> 原型对象(有`Symbol.iterator`) -> `Object.prototype`

执行`itor.next()`才会执行fn中的代码

- 把之前传递的实参赋值给形参
- this->window
- 遇到yield或return结束
- 返回一个对象 `{value:xxx, done:false/true}`

```js
function* fn(x,y) { 
    console.log('hello');
    console.log(x, y);
    console.log(this);
    return 10
}

let itor = fn(111, 222)
console.log(itor); // Object [Generator] {}
console.log(itor.next()); 
// hello 111 222 Window  
// { value: 10, done: true }
```

`itor.next()`遇到yield会停止，**yield后的值作为返回对象中的value**。举例：

```js
function* generator() { 
    console.log('A');
    yield 10;
    console.log('B');
    yield 20;
    console.log('C');
    yield 100;
}
let itor = generator()
console.log(itor.next());
console.log(itor.next());
console.log(itor.next());
console.log(itor.next());

/**
A
{ value: 10, done: false }
B
{ value: 20, done: false }
C
{ value: 100, done: false }
{ value: undefined, done: true }
 */
```

`itor.throw()`：手动抛出异常，结束函数执行

`itor.return(xxx)`：结束函数执行，返回`{value: xxx, done: true}`



**每次next传递的参数，会作为上一次yield执行的返回值。**

```js
function* generator() {
    let res = yield 1;
    console.log(res);
    
    res = yield 2;
    console.log(res);
    
    res = yield 3;
    console.log(res);
}
let itor = generator()
console.log(itor.next(100)); // 第一次执行next传递的值没有用
console.log(itor.next(200)); // 将200赋值给第一个res。每次next传递的值，会作为上一次yield执行的返回值
console.log(itor.next(300)); // 将300赋值给第二个res。
console.log(itor.next());
/**
    { value: 1, done: false }
    200
    { value: 2, done: false }
    300
    { value: 3, done: false }
*/
```

`yield*`：表示进入到新的generator函数中

```js
function* generator1() { 
    yield 1
    yield 2
}
function* generator2() { 
    yield 3
    yield* generator1() // yield*：表示进入到新的generator函数中
    yield 4
}
let itor = generator2()
console.log(itor.next()); // { value: 3, done: false }
console.log(itor.next()); // { value: 1, done: false }
console.log(itor.next()); // { value: 2, done: false }
console.log(itor.next()); // { value: 4, done: false }
```

### async/await原理：用generator实现

案例：并行发送三次请求，间隔1s、2s、3s

```js
// 模拟发送请求
const query = interval => {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            resolve(interval)
            // reject('fail')
        }, interval)
    });
}
```

用generator和手动next实现，代码有些不美观：

```js
function* generator() {
    let value = yield query(1000)
    console.log('第一次请求', value);
    value = yield query(2000)
    console.log('第二次请求', value);
    value = yield query(3000)
    console.log('第三次请求', value);
}

let itor = generator()
// itor.next().value：第一次请求的promise实例
itor.next().value.then(val => {
    // val：第一次请求的结果
    console.log(val); // 1000
    itor.next(val).value.then(val => {
        console.log(val); // 2000
        itor.next(val).value.then(val => {
            console.log(val); // 3000
            itor.next(val)
        })
    })
})
```

改进如下：

`AsyncFunction`：生成器执行器。是 **`co` 库的核心实现**，也是 `async/await` 的底层原理。

```js
// 需求：并行发送三次请求，间隔1s、2s、3s
const isPromise = function isPromise(x) {
    if (x !== null && /^(object|function)$/i.test(typeof x)) {
        var then
        try {
            then = x.then
        } catch (e) {
            return false
        }
        if (typeof then === 'function') return true
    }
    return false
}

function* generator() {
    let value = yield query(1000)
    console.log('第一次请求', value);
    value = yield query(2000)
    console.log('第二次请求', value);
    value = yield query(3000)
    console.log('第三次请求', value);
}

// co.js 核心实现
function AsyncFunction(generator, ...params) {
    return new Promise((resolve, reject) => {
        // 1. 创建生成器实例，并传入参数
        let itor = generator(...params);

        // 2. 定义递归的 next 函数
        const next = val => {
            let { value, done } = itor.next(val); // 执行生成器，val 是上一个 yield 的结果
            if (done) {
                resolve(value);  // 生成器执行完毕，value 是 return 的值
                return;
            }
            // 3. 确保 value 是一个 Promise
            if (!isPromise(value)) {
                value = Promise.resolve(value);
            }
            // 4. 等待 Promise 决议，将结果传回生成器继续执行
            value.then(val => next(val))
                 .catch(reason => {
                     reject(reason);          // 外层 Promise 拒绝
                     itor.throw(reason);     // 在生成器内部抛出错误
                 });
        };
        // 5. 启动生成器
        next();
    });
}

AsyncFunction(generator).then(val => {
    console.log('请求都成功 ', val);
}).catch(reason => {
    console.log('某次请求失败', reason);
})
```



## async await

Promise + Generator的语法糖。

async是对函数的修饰：`async function xxx(){ ... }`

- ==让函数的返回值自动变为Promise实例==
  - 函数执行过程中报错，则返回状态是rejected，值为报错原因的实例
  - 如果执行正常，再看返回值
    - 返回值是新的Promise实例，则以这个实例为主
    - 其他情况，都是返回一个状态为fulfilled，值为返回值的Promise实例

```js
const fn = async () => { console.log(a);
 };
console.log(fn1()); // Promise { {<rejected>: ReferenceError: a is not defined }

const fn1 = async () => { return 10; };
console.log(fn()); // Promise { fulfilled 10 }

const fn2 = async () => { return Promise.resolve(100); };
console.log(fn3()); // Promise { fulfilled 100 }

const fn3 = async () => { return Promise.reject(100); };
console.log(fn3()); // Promise { rejected 100 }
```



可以在async函数中使用await。await监听promise实例的状态，从而决定去做什么事。`let xxx = await [promise实例]`

- ==await后面是一个Promise实例==（如果不是，也会自动包装成Promise实例）。`await 14` ==> `await Promise.resolve(14)`
- await会等待后面的实例状态为成功后，再把当前上下文中await下面的代码执行，xxx是实例状态为成功返回的结果
- 如果await后面的实例状态为失败，则函数中后续代码不会执行（如果没有对错误进行处理，控制台会爆红，但不影响其他代码执行）
  - 可基于try/catch实现对await后实例为失败状态的处理，避免爆红

当函数内部的所有await处理完，且对应的实例都是fulfillled，才会让handler执行的返回值是成功的promise实例。如果代码执行报错，或者其中某个await后面的实例是失败的，则handler返回值也是失败的

```js
const handler = async () => {
    await sleep(2000)
    console.log("1");
    await sleep(1000)
    console.log("2");
    await sleep(3000)
    console.log("3");
}

handler.then(() => {
    console.log('ok');
}).catch(() => { 
	console.log('fail');
})
```

promise语法糖：成功情况

```js
const query = () => {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            reject('fail')
        }, 1000)
    });
}

(async function (params) {
    try {
        let value = await query()
        console.log(value);
    } catch (error) {
        console.log(error);
    }
})()

query().then(value => {
    console.log(value);
}, reason => {
    console.log(reason);
})
```

```js
const query = () => {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            resolve({ code: 0, data: [1, 2, 3] })
        }, 1000)

}

(async function (params) {
    let value = await query()
    console.log(value);
})()
// 等同于
query().then(value => {
    console.log(value);
```
